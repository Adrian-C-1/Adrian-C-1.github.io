#Solve

ROP gadgets:

By executing the binary and comparing my input with the return pointer on the stack, I concluded that I can type:

The stack should look like this:

I’m trying to execute execve("/bin/sh", 0, 0).

read returns the number of bytes it reads in rax.
write returns the number of bytes it writes.

  • rax = 0
  • rdi = 0 (read) / 1 (write)
  • rsi = 0x
  • rdx = count

0x401017 = vuln
0x401003 = reread

How do I put whatever I want into rax? (From the beginning of a buffer overflow.)

  1. Return to reread.
  2. Read n characters.
  3. The result is in rax.
  4. Continue the ROP chain.

execve("/bin/sh") requires:

  1. 0x3b in rax.
  2. "/bin/sh" in rdi.
  3. 0 in rsi.
  4. 0 in rdx.

0x000000000040106f : mov rsi, rdi ; mov rdx, rdi ; syscall is unfortunately useless because we cannot put the string in rdi.

execveat(0, "/bin/sh", 0, 0, ...):

  1. 0x142 in eax
  2. dfd in rdi.
  3. /bin/sh in rsi.
  4. 0 in rdx.
  5. 0 in r10.
  6. 0 in r8.

This is achievable; see below.

Immediately before the first ret:

  • rax contains len(input) (for testing, it is 5).
  • rsi points to the input string.
  • rdi is 0.
  • rdx is 0x400.

How do I get "/bin/sh"?

ROP back into vuln and write /bin/sh\x00\n. (b"/bin/sh\x00aa..aa\n" is 9 bytes; add aa until the return value of read is 0x3b).

  • rax contains 0x3b.
  • rsi points to "bin/sh".
  • rdi is 0.
  • rdx is 0x400.

Then immediately execute a syscall to run execveat (for 0x141 instead of 0x3b), as described above.

After writing this, I realized that the first part of the payload is useless because I have enough space in a single payload to write /bin/sh\x00, overwrite the return address, and make rax contain what I want.

So, an even more minimal solution:

flag

deadface{P13c3_By_P13c3_T#3_D34D_SH477_R153}
